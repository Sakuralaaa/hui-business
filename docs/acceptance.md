# 云端验收与朋友试用

## 已加入自动验收

GitHub Actions 执行：Prisma 生成、TypeScript 检查、前后端构建、核心单元测试、PostgreSQL API / Worker 集成测试、外部 Python 上传程序验证，再构建和发布固定提交镜像。

测试覆盖长文本 ID、数值精度异常、零与缺失、旧版本及冲突、Manifest 越界、订单头去重、成本缺失、广告无归因、零分母、订金独立、十进制计算、CSV 公式防护。集成测试覆盖上传 → 解析 → 预览 → 确认 → 重复文件、幂等重试、另一企业无法访问、凭据不可读取业务、撤销及确定性分析。

## 上线前继续补充

| 项目 | 验证方法 |
|---|---|
| 凭据过期 / 错店铺 / 错任务 | 服务端时间推进及越权清单 |
| 文件异常 | XLSX 公式与损坏、JSON 深度、ZIP 炸弹和目录越界 |
| 中断恢复 | 终止上传、Worker 和确认进程，验证原件/事务与重试 |
| 权限细分 | 财务字段、团队店铺、知识、缓存及行动草稿 |
| AI 质量 | 相同事实包评估编造规格、认证、交期、错误数字和证据 |
| 性能 | 4C8G、100k CSV；记录解析时间、确认时间和分页 p95 |
| 恢复 | 空实例恢复数据库、对象与密钥，抽查原件及快照 |

解析校验目标 ≤10 分钟、普通分页 p95 ≤3 秒，需实际测量。导出、网络、模型耗时分别计量，不作为后端性能。

## 发给朋友的第一轮任务

先在演示企业操作一次商品、询盘、订单、费用、内容检查和指标生成。观察是否能理解“缺少成本、广告归因未知、部分数据”提示，并确认行动流程是否增加负担。

愿意继续时，在自己的已授权 Accio 环境中尝试：一个商品资料文件、最近七个完整自然日经营报表、少量订单或询盘明细。只提供愿意用于试用的资料；不交给本系统密码或 Cookie。记录原生导出 / 页面提取 / 摘要、真实字段、稳定 ID、时间范围、行数上限和可见额度消耗。

真实文件到位后补充 MappingProfile，核对来源控制总額并手工抽查几笔；未确认完整性时按实际覆盖使用。同一批输入分别试现有工具与本系统，不预先认定优于 Accio。

反馈记录字段：任务、日期、输入数据范围、采集耗时、处理耗时、模型成本、结果可核查性、实际采纳动作、修改次数、增加的操作负担、继续使用意愿、最希望改进的三点。

定时采集、真实官方 API、平台刊登最终读回及更深自动化在手动导入稳定后推进；更新查询或重叠期间导出要能补到历史退款和售后变化。
